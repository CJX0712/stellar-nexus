# ADR-0004 归因校验用 IDF 加权词汇覆盖度，不训 NLI 模型

- 状态：采纳
- 日期：2026-09-23
- 作者：晨星

## 背景

系统要对每条答案做「是否言之有据」的判定。这是把「RAG 演示」和「可自证系统」
区分开的关键能力：不能只把引用贴上去就宣称可信，必须真的去核。

## 备选方案

**A. 训 / 微调一个 NLI（自然语言推理）模型。**
效果上限最高，但要标注数据、要训练、要 GPU，且产物体积大。与「复用开源成果、
零训练」的约束冲突。

**B. 用 LLM 做蕴含判定（`LLMVerifier`）。**
零训练，质量不错。但：① 每个答案多一次生成，CPU 上 10s 级；
② **不确定性不可接受** —— 校验器的输出必须可复现，否则门禁就没意义。

**C. IDF 加权的词汇覆盖度（`EvidenceVerifier`）。**（本决策）

**D. 直接用字符串包含判断。**
太粗：改写、同义替换全部判失败，误杀率极高。

## 决策

采用 C 作为默认，B 作为可选实现（`LLMVerifier` 同样实现 `Verifier` 协议）。

算法：

1. `split_claims(answer)` —— 按句切分，并在转折词（但是 / 然而 / 不过 / 因此…）处再切一次，
   因为转折后的内容常是新断言。
2. 对每条断言，取其 token 在证据文本中的**覆盖率**，每个 token 按 **IDF 加权**。
3. 未覆盖部分按 `unsupported_penalty=0.35` 折扣。
4. `groundedness = 支持断言数 / 断言总数`；`断言总数为 0 时取 0.0`。

## 理由

### 为什么必须 IDF 加权

这一条是实测踩出来的。不加权时，几乎所有断言都能被判定为「被支持」，
因为「的 / 了 / 是 / 在 / 和」这类虚词在任何中文文本里都大量出现，
覆盖度天然接近 1。**校验器于是完全没有区分度** —— 这是最危险的一类缺陷：
它不会报错、不会失败，只是安静地给出「一切正常」。

`test_verify.py` 里有一条**反向断言**守着这个性质：

```python
# 把证据换成无关文本，忠实度必须显著下降
assert tampered.groundedness < 0.3   # 实测 0.000
```

只测「正确时分数高」是不够的 —— 那只证明它会给高分，证明不了它能识别错误。

### 为什么不用 LLM 做默认校验

校验器的输出会进入 CI 门禁。门禁必须**确定**：同一份输入两次运行结论必须一致。
LLM 采样会破坏这一点（即便 `temperature=0`，不同版本/硬件下仍可能有细微差异）。
把不确定性引入质量门禁，等于把门禁变成掷骰子。

### 断言语义的一个坑

`groundedness` 在**断言数为 0** 时定义为 `0.0` 而不是 `1.0`。
直觉上「没有断言 → 没有错误 → 满分」，但那样一个**空答案**就能拿到满分，
门禁会被空输出骗过。这个约定写在 `core/types.py` 的文档字符串里。

## 代价与补救

| 代价 | 补救 |
|---|---|
| 词汇覆盖度不等于语义蕴含 | README 与文档明确它是**启发式**，不宣称等价于 NLI |
| 同义改写的断言可能被误判为无据 | `unsupported_penalty` 缓解；`LLMVerifier` 作为可选高精度路径 |
| 中文切词质量直接影响校验质量 | 与检索共用 `core/text.tokenize`，一处改进两处受益 |
| 虚词抑制靠 IDF 而非停用词表 | IDF 更自适应：语料变了不用改代码 |

## 反悔路径

```python
# 在 pipeline 里换一行即可，协议相同
self.verifier = LLMVerifier(self.llm)
```

或按场景混用：离线门禁用 `EvidenceVerifier`，线上用 `LLMVerifier`。
